# M4.3.3.5.3 — Socket.IO Publication and Authorized Event Delivery

**Status:** Implementation submitted for local acceptance  
**Branch:** `feat/m4.3.3.5.3-realtime-event-delivery`  
**Base:** `develop`

## Objective

Publish durable Infrastructure Operation events to authorized Desk users and provide an authorized, cursor-based event-history API for reconnect and gap recovery.

## Realtime delivery

- The event service invokes the dedicated publisher only after the immutable event record has been inserted.
- Publication uses Frappe's `frappe.publish_realtime` API with `user=<recipient>` and `after_commit=True`.
- No site-wide, doctype-wide, document-wide or client-selected room is used.
- Recipients are derived from persisted operation ownership:
  - the operation's `initiated_by` user;
  - enabled users with the platform `System Manager` role.
- The worker's current session identity is not used to select recipients.
- The publisher schedules the same versioned `operation_event` envelope for each authorized recipient.
- Event execution state is mapped from the event type so a fast subsequent transition cannot rewrite the state associated with an earlier event.
- The realtime publisher is best-effort. Errors are logged without propagating into the durable operation transaction.

## Published envelope

The publisher emits only the stable public event envelope:

- `schema_version`
- `event_id`
- `operation_id`
- `correlation_id`
- `sequence`
- `event_type`
- `occurred_at`
- `execution_state`
- `phase`
- `progress`
- `message`

The internal `event_data` field is intentionally excluded from Socket.IO delivery. Full results and restricted diagnostics remain available only through the authorized operation snapshot and server-side logs.

## Event history and reconnect

Added whitelisted method:

`dt_master.api.operations.get_operation_events`

Parameters:
- `operation_id`: required operation identifier.
- `after_sequence`: exclusive cursor; defaults to 0.
- `limit`: page size from 1 through 100; defaults to 50.

The endpoint:
- authorizes the initiator or a platform System Manager before reading events;
- returns events in ascending sequence order;
- returns only the public event envelope fields;
- returns `next_after_sequence` and `has_more` for bounded pagination;
- does not trust socket delivery as a source of truth.

A client reconnects by requesting events after its last observed sequence. Duplicate or out-of-order socket messages can be reconciled against the durable sequence.

## Explicitly out of scope

- Global Task Manager UI and browser listener lifecycle.
- Active/recent operation list API.
- Client-side deduplication, gap detection and replay orchestration.
- Progress callbacks from operation handlers.
- Heartbeat scheduling.
- Cancellation, retry, resource leases, fencing and crash recovery.

These remain later M4.3.3 packages. This package provides the server-side publication and history primitives only.
