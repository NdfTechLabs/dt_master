# M4.3.NP.1 — Host OS Observation Contract

**Status:** Implemented for review; support matrix approved 2026-11-20.  
**Scope:** Read-only Infrastructure Node Host inspection only.

## Approved support matrix (policy 1.0.0)

| Distribution ID | Version ID | Architecture | Support |
|---|---:|---|---|
| `ubuntu` | `22.04` | `amd64` | Supported |
| `ubuntu` | `24.04` | `amd64` | Supported |
| `debian` | `12` | `amd64` | Supported |

The matrix is an exact-match allowlist. Other releases and architectures are still inspected and reported as `Unsupported`; missing or unknown identity values are reported as `Unknown`. `ID_LIKE` is informational and does not confer support.

## Observation contract

The existing `inspect_host_runtime.sh` remains the single Host probe and continues to use the existing SSH script contract with `use_sudo=False`. It retains hostname, display OS name, CPU, memory, root filesystem availability and Bench availability, and adds:

- Canonical distribution ID, version ID, version codename and ID_LIKE.
- Raw kernel architecture and normalized architecture (`x86_64 → amd64`, `aarch64 → arm64`, plus recognized 32-bit forms).
- Detected package manager and service manager; unknown values are explicit.
- Support policy version and exact-match support result in the adapter response.

The versioned schema is `schemas/infrastructure-node-host-inspection-v1.schema.json`. The adapter validates required observation fields and capacity measurements before returning a successful inspection. Unsupported identity is a successful observation with an unsupported classification, not an SSH/inspection failure.

## Boundaries

- No sudo, package installation/update, repository or key changes, service mutation, Docker commands, daemon configuration, filesystem writes or caller-controlled commands.
- No baseline readiness is asserted by this work package. `os_support_status` is only OS eligibility evidence; it does not assert Docker readiness or that a Node is prepared.
- The existing generic Host preflight behavior remains unchanged; its response carries the OS support classification separately.
- Docker-specific observations remain owned by the existing M4.3.2 Docker inspection path.

## Acceptance evidence required

Run the focused Host adapter and static script tests on the implementation branch, then the repository's normal lint/pre-commit checks. Confirm CI results on the PR. Live host evidence is not required for this read-only contract.
