# M4.3.3.6.1 — Authorized Task Manager Operation List API

**Status:** Submitted for local acceptance  
**Branch:** `feat/m4.3.3.6.1-task-manager-api`  
**Base:** `develop`

## Objective

Provide the global Desk Task Manager with a bounded server-side snapshot of active and recently completed Infrastructure Operations.

## API

Added the whitelisted method:

`dt_master.api.operations.get_operations`

Parameters:
- `active_limit`: number of active operations, 1–100; defaults to 50.
- `recent_limit`: number of terminal operations, 0–50; defaults to 20.

Response:
- `active`: Pending Dispatch, Queued, Running, Retry Waiting, Cancellation Requested and Recovery Required.
- `recent`: Succeeded, Failed and Cancelled, ordered by most recently modified.
- Each item contains only operation identity, correlation, type, target, initiating context, lifecycle state, attempt count, timestamps and safe error summary.

## Authorization and data boundary

- Guest sessions are rejected.
- Ordinary authenticated users see only operations they initiated.
- System Managers may see platform-wide operations, matching the existing single-operation read policy.
- Query limits are validated and bounded.
- Request/result payloads, execution identity, lock metadata and internal diagnostics are not returned.
- The endpoint is a snapshot only. Event history and realtime delivery remain separate and authoritative.

## Scope boundary

This package supplies the authorized snapshot API only. The global Desk asset, Task Manager panel, Socket.IO listener, browser sequence reconciliation and reconnect replay orchestration remain in the subsequent UI implementation step. Cancellation and retry controls are not exposed.
