# M4.3 N2.2.2 — Docker Package Update Metadata Checks

**Status:** Read-only implementation; no package mutation or metadata refresh.

## Scope

The host.node.docker.updates.check observation reports installed and candidate versions for the fixed Docker CE package family: Docker Engine, CLI, containerd.io, Buildx and Compose plugin.

On Debian/Ubuntu hosts it reads cached APT metadata using fixed apt-cache policy queries and installed package state. It reports candidate repository origin and the age of the newest cached APT index. Unsupported package managers return an explicit Unsupported result.

## Safety

- Does not run apt update, apt-get update, install, upgrade, remove or service commands.
- Does not accept package names, repository URLs, commands, paths or privilege options from the operation payload.
- Uses a fixed package allowlist and bounded subprocess time/output.
- Does not use sudo.
- Stale or unavailable APT metadata produces Unknown; it cannot claim the host is up to date.
- Runs through the existing Infrastructure Operation coordinator, RQ worker, runtime adapter and Task Manager.

## Freshness policy

- Fresh: newest cached index is at most 24 hours old.
- Aging: over 24 hours and at most 7 days old.
- Stale: older than 7 days.
- Unavailable: no readable cached index timestamps.

An Aging result is not treated as definitive up-to-date status. N2.2.2 does not refresh metadata.
