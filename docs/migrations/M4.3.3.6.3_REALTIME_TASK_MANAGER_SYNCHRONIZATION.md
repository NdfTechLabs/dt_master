# M4.3.3.6.3 — Realtime Task Manager Synchronization

**Status:** Submitted for local acceptance  
**Branch:** `feat/m4.3.3.6.3-realtime-task-manager-sync`  
**Base:** `develop`

## Objective

Keep the global Desk Task Manager synchronized with durable Infrastructure Operation events, including events missed while the browser is disconnected or refreshed.

## Implementation

- Listen for the server-published `operation_event` user-room event through `frappe.realtime`.
- Do not subscribe to operation rooms or accept client-selected room names; server-side recipient authorization remains authoritative.
- Use `get_operations` as the bounded authorized snapshot.
- Reconcile each operation using the authorized `get_operation_events` endpoint and its exclusive sequence cursor.
- Apply only contiguous event sequences. Duplicate and already-consumed events are ignored by the sequence cursor.
- If an event arrives during an active replay, schedule another reconciliation after the current replay completes.
- On Socket.IO reconnect, reload the snapshot and replay persisted history for all visible operations.
- On initial mount and manual refresh, replay history as well, covering page reloads and missed socket delivery.
- Display the latest safe event message and phase alongside the current execution state.
- Keep operation records and durable event history authoritative; socket delivery is only a notification.

## Security and resilience

- The server already publishes to authorized user rooms only.
- Every event-history request is independently authorized by the server.
- No event payload, result payload, execution identity, lock metadata or internal diagnostics are rendered.
- Event values are rendered with `textContent`.
- Realtime publication remains best-effort; missed events are recovered from persisted history.
- A sequence gap is not silently skipped. Replay stops and retries on a later refresh/reconnect.

## Browser acceptance matrix

1. Start an operation and confirm the panel state changes without manual refresh.
2. Confirm subsequent progress/log events update the latest event message and phase.
3. Complete or fail an operation and confirm it moves to the appropriate Recent state.
4. Reload Desk during a running operation and confirm the snapshot plus event history restore its latest state.
5. Disconnect/reconnect Socket.IO, allow events to occur while disconnected, and confirm history replay catches up.
6. Confirm duplicate/out-of-order notifications do not regress state or duplicate event presentation.
7. Confirm a normal user cannot retrieve another user's operation history; confirm System Manager access follows the existing server policy.
8. Confirm minimizing the panel does not stop synchronization or operation execution.

No database migration is required.
