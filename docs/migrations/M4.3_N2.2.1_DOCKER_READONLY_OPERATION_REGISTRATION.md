# M4.3 N2.2.1 — Register Docker Read-only Lifecycle Operations

**Status:** Implementation ready for local validation.  
**Scope:** Register Docker Engine inspection and readiness preflight through the existing Infrastructure Operation coordinator.

## Registered operations

- `host.node.docker.inspect`
- `host.node.docker.preflight`

Both operations use the existing `docker-compose-v1` adapter and its read-only `inspect` / `preflight` methods. They are dispatched by the existing Frappe RQ worker and produce the standard durable operation result for Task Manager.

## Safety boundaries

- Both requests accept an empty payload only.
- The Infrastructure Node target is authorized by the N2.1 System Manager, Node read-permission and verified-SSH contract.
- Adapter identity, runtime type and method are server-selected; callers cannot choose them.
- A dedicated `node-docker-observation:{node_name}` lock is used. It is intentionally distinct from the Node Docker mutation lock.
- No mutation operation is registered by this increment.
- No package-manager commands or scripts are introduced.

## Deferred operations

`host.node.docker.updates.check` requires a separate package metadata observation handler. `host.node.docker.verify` requires a defined postcondition contract. They remain unregistered until those handlers are implemented.

All Engine and Compose mutations remain unregistered until the fixed privilege boundary and trusted executors are accepted.
