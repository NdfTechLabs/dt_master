# M4.3 N2.4.4 — Docker Privilege Readiness Inspection

## Purpose

Add a read-only, fail-closed observation of the trusted Docker helper privilege boundary established by N2.4.2 and N2.4.3. This increment does not install, repair, or modify the helper, sudoers policy, packages, Docker Engine, or services.

## Probe

The fixed check_docker_privilege_readiness.sh wrapper invokes the colocated Python probe. The adapter supplies only the configured SSH username as EXPECTED_SSH_USER; it does not accept caller-selected paths, commands, helper arguments, or privilege flags.

The probe checks:

- SSH execution identity equals the configured Infrastructure Node SSH user.
- The helper is a regular root:root 0755 file with the pinned N2.4.2 SHA-256 digest.
- Every managed helper parent is a real root-owned directory and is not group/world writable.
- The managed sudoers file is a regular root:root 0440 file whose complete contents equal the exact no-argument rule rendered for the configured SSH user.
- visudo -cf accepts the managed policy.
- sudo -n -l permits the exact helper invocation.
- The helper self-test returns the expected bounded JSON response with effective UID 0.

The probe uses fixed system paths, bounded subprocess timeouts, a bounded output contract, and no package-manager or filesystem mutation commands.

## Result and integration

The result schema is 1.0.0, with status Ready, Not Ready, or Incomplete, timestamp, identity, helper and sudoers observations, named checks, and bounded diagnostics.

Docker inspection includes the privilege observation. Docker preflight is blocked when the privilege boundary is Not Ready and degraded when inspection is Incomplete. Existing Docker runtime inspection remains read-only. No Docker package lifecycle mutation capability is registered or enabled by this change.

## Acceptance

- Contract validation rejects unknown fields, check names, and statuses.
- Script syntax and fixed-path/no-mutation contract tests pass.
- Adapter tests prove Not Ready blocks preflight and Incomplete degrades it.
- Runtime acceptance is performed later on a disposable non-production Node under N2.4.6; do not run installers on production Nodes as part of N2.4.4.
