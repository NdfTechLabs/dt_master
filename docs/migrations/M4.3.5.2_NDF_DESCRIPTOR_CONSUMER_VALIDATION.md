# M4.3.5.2 — NDF Descriptor Consumer and Validation

**Status:** Initial pure validation implementation prepared; local execution and review pending.  
**Branch:** `feat/m4.3.5.2-ndf-descriptor-validation`  
**Depends on:** M4.3.5.1 readiness baseline; NDF PDD v1.0.0 and service descriptor v1.0.0.

## 1. Scope

This work package introduces a pure Python validation boundary for NDF Product Deployment Descriptors (PDDs) and referenced service descriptors. It does not retrieve artifacts, verify signatures/attestations, allocate resources, render Compose, or mutate infrastructure.

The validator consumes the authoritative JSON Schema object supplied by a trusted NDF contract bundle. It does not silently download a schema or treat a schema bundled with an untrusted descriptor as authoritative.

## 2. Implemented

- Strict JSON parsing helper rejects duplicate object keys and non-finite numeric constants.
- NDF-JSON-CANONICAL-V1 implementation: UTF-8, recursively sorted keys, compact separators, preserved non-ASCII text and no floating-point values.
- PDD JSON Schema Draft 2020-12 validation using `jsonschema`, including format checks.
- PDD canonical integrity digest verification, descriptor identity derivation, immutable image reference consistency and optional expected image-reference binding.
- Exact eleven-entry M4.2.5 evidence inventory validation, safe evidence paths, duplicate name/path rejection and cross-field evidence digest binding.
- Runtime inventory/platform/framework identity checks.
- Composition application/service/external-requirement identity collision checks, dependency reference validation, self-dependency and cycle rejection.
- Service requirement declarations cross-checked against PDD composition and service requirement state semantics.
- Service descriptor validation against its authoritative schema, exact PDD-bound raw-byte SHA-256, expected service identity and digest-pinned container image.
- Pinned NDF PDD and service schema snapshots are included as test fixtures only. They are not runtime schema authority. Snapshot source commit: NDF `main` at review time; PDD schema blob `825002d94b7dc66b61553bc230a9fcd0054ae7b0`; service schema blob `bcec9d265f74c3e464ee0655f847dd91fcfa7b79`.

## 3. Trust and enablement boundary

A successful validation report explicitly returns:

- `trust_status = not_verified`
- `deployment_authorized = false`

This is deliberate. PDD schema and content integrity do not prove publisher identity or artifact provenance. NDF image/PDD signature and attestation verification, candidate origin and trust binding remain in the M4.4 handoff. The validator must not convert a structurally valid PDD into a trusted or deployable artifact.

The PDD v1.0.0 contract also explicitly says service descriptors currently do not define a complete executable topology. This implementation does not infer commands, entrypoints, ports, probes, storage mounts, backup semantics, secret values or environment-specific configuration. Such fields remain unavailable until NDF publishes a typed contract extension.

## 4. Dependency

The app declares `jsonschema>=4.18,<5` to provide Draft 2020-12 validation. Schema retrieval/distribution and trust pinning for production use are separate integration work; test snapshots are not used as an implicit runtime fallback.
