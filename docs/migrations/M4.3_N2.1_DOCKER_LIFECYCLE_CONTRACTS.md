# M4.3 N2.1 — Docker Lifecycle Request Contracts

**Status:** N2.1 contract foundation implemented; read-only lifecycle operations subsequently registered in N2.2.1–N2.2.3. Mutating operations remain disabled.  
**Scope:** Typed payload validation, authorization helper, and explicit Node-scoped mutation lock resolver.

## Operation catalogue

The contract catalogue defines twelve operation IDs:

- Read-only: `host.node.docker.inspect`, `host.node.docker.preflight`, `host.node.docker.updates.check`, `host.node.docker.verify`.
- Mutating: Engine install/upgrade/downgrade/uninstall and independent Compose install/upgrade/downgrade/uninstall.

N2.1 defined the identifiers and request contracts. Subsequent increments registered the four read-only operations:
- N2.2.1 registered inspect and preflight.
- N2.2.2 registered the cached APT updates check.
- N2.2.3 registered read-only verification.

The eight mutating operations remain unregistered. Registering a mutation before its trusted handler, automated privilege boundary and postcondition verification exist would allow a request to be accepted without a safe execution path.

## Payload rules

- Read-only operations accept an empty object only.
- Install and uninstall require `confirm: true`.
- Upgrade and downgrade require `confirm: true` and one explicit `target_version`; the server resolves the compatible package set. Callers cannot supply package names.
- An optional `expected_state_fingerprint` is a lowercase SHA-256 digest used to detect stale confirmation state.
- Unknown fields are rejected. No command, script, path, package, repository, SSH target, sudo flag or environment override is accepted.
- The payload never contains credentials or secret material.

## Authorization and locking

The authorization helper requires System Manager, Infrastructure Node read permission and verified SSH access. It is intended to be called both before acceptance and again in the worker.

All Docker package/service mutations on a Node share the explicit lock key `node-docker:{node_name}`. Read-only checks use a separate observation lock namespace. The existing generic worker lock fallback remains unchanged for unrelated operations.

## Recovery and execution boundary

N2.1 did not introduce an execution handler. The read-only N2.2.x handlers use the existing Infrastructure Operation coordinator, RQ worker, operation bridge, runtime adapter, event stream and Task Manager.

Privileged mutations remain disabled pending N2.4. The agreed design retains the configured SSH execution user and automates root-owned fixed helpers plus a narrowly scoped sudoers policy; no second Linux user, blanket sudo rule, generic `sudo bash`, or caller-controlled privilege option is permitted. See [N2.4.1 Automated Docker Privilege Boundary](M4.3_N2.4.1_AUTOMATED_DOCKER_PRIVILEGE_BOUNDARY.md).

An uncertain outcome, lost lease, timeout or failed postcondition must enter Recovery Required; package mutations must never be blindly retried.
