# M4.3 Node Inspection and SSH Connection Operations

## Scope

These operations belong to the Infrastructure Node doctype. Bench lifecycle and
site operations are not changed by this work; their ownership is moving to the
Bench Environment doctype.

## Operator actions

- **Inspect Node** queues `host.node.inspect`, which invokes the existing
  read-only Host adapter inspection.
- **Test Node Connection** queues `host.node.connection.check`, which uses
  the configured SSH transport to execute the fixed
  `bin/node/test_node_connection.sh` probe.

The connection probe prints only the fixed marker `DT_MASTER_SSH_OK`. It does
not use sudo, accept caller-supplied commands, install packages, or modify host
state. The adapter requires the exact marker and a successful SSH exit status.
The result includes the SSH round-trip duration in milliseconds.

Both operations:
- require System Manager and a node with verified SSH access;
- use the existing durable Operation Coordinator and Task Manager;
- are read-only, single-attempt operations with a Node-scoped observation lock;
- have stable Task Manager labels matching the Infrastructure Node buttons.

## Remote script deployment

Deploy `dt_master/scripts/bin/node/test_node_connection.sh` to the configured
node scripts bundle at:

```text
<scripts_base_dir>/bin/node/test_node_connection.sh
```

The existing Host inspection script must already be deployed in the same
bundle. The SSH test intentionally does not use the generic `test.noop`
operation: that operation validates worker dispatch only and does not contact
an Infrastructure Node.

## Bench boundary

No Bench action is migrated or renamed here. Bench operations remain outside
this Node-scoped change and will be moved to the Bench Environment doctype in
the dedicated Bench work.
