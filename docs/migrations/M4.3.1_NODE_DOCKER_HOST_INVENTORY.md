# M4.3 N1 — Docker Host Inventory Probe

**Status:** Initial implementation on `feat/n1-docker-host-inventory`.  
**Scope:** Read-only host evidence for Docker lifecycle planning.  
**Does not:** Refresh package indexes, install/remove packages, restart services, or mutate Docker workloads.

## Implementation

`dt_master/scripts/bin/docker/inspect_docker_host.py` provides a standard-library-only probe that emits a compact JSON object with schema version `1.0.0`.

It collects:
- OS identity/version/codename, architecture and kernel from `/etc/os-release` and Python platform metadata;
- detected package manager (`dpkg`, `rpm`, `apk`, `pacman`, or Unknown);
- installed versions for an explicit Docker package allowlist (Docker CE family and distribution packages);
- systemd active state for Docker and containerd where systemd is available;
- Docker workload counts (running and total containers) when the current unprivileged identity can query the system Docker socket.

The workload probe collects IDs only and returns counts. It does not return container names, images, labels, environment, logs, networks or volume contents. If the Docker daemon is unavailable or access is denied, workload counts are null and `available=false`.

## Safety properties

- All subprocess invocations use fixed argument arrays; no shell is involved.
- Commands have bounded timeouts and output.
- No sudo or privilege escalation.
- No package manager metadata refresh or candidate-version query.
- Package names are selected from a fixed allowlist; arbitrary query output is discarded.
- No Docker workload mutation.
- Unsupported package managers are reported without failing the whole inventory.

## Current limitation / next N1 increment

This probe is an independently testable inventory component. It is not yet merged into the existing `inspect_docker.sh` snapshot or Docker adapter result. The next N1 increment will integrate it into the durable Docker inspection result and validate the combined versioned contract before N2 operation registration.

Package candidate versions and metadata freshness belong to the later read-only update-check capability (N5); they are intentionally not inferred from installed package inventory.
