# M4.3 N2.2.3 — Docker Read-only Verification

**Status:** Implemented for local and CI acceptance; read-only operation only.  
**Scope:** Verify Docker CLI, Engine and Compose v2 using the existing Infrastructure Node inspection contract.

## Operation

The registered operation is `host.node.docker.verify`. It is dispatched through the existing Infrastructure Operation coordinator, Frappe RQ worker, runtime adapter bridge and Task Manager.

The operation targets an Infrastructure Node and reuses the fixed `inspect_docker.sh` entrypoint through the Docker runtime adapter. It does not introduce another task manager or a new remote script.

## Verification semantics

The result contains `verification_status`, component observations and structured diagnostics.

| Status | Meaning |
| --- | --- |
| `Verified` | Docker CLI is installed with path and client version; Engine is reachable with a server version; Compose v2 is installed, has a version and reports compatible; inspection completed successfully. |
| `Not Verified` | A required component is definitively absent, unavailable or incompatible. |
| `Incomplete` | One or more required observations are unknown, missing or the underlying inspection was partial/unsuccessful, so verification cannot be asserted. |

Operation outcomes map to the status as follows:

- `Verified` → `succeeded`
- `Not Verified` → `failed`
- `Incomplete` → `partial`

A failure to observe the Node does not imply that Docker is absent. It produces an incomplete verification result with the underlying inspection diagnostics.

## Safety boundary

Verification is strictly read-only:

- No APT metadata refresh or package installation.
- No service start, stop or restart.
- No Docker daemon configuration changes.
- No sudo or privilege escalation.
- No caller-controlled script, command, path, package or remote endpoint.
- No mutation of Infrastructure Node lifecycle state.

The operation uses the existing Node observation lock namespace and the existing System Manager / verified SSH authorization contract. Docker package mutations remain unregistered.
