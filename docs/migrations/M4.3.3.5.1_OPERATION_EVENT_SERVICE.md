# M4.3.3.5.1 — Operation Event Service

## Status

Implementation branch: `feat/m4.3.3.5.1-event-service-contract`

This task introduces the central persistence service for Infrastructure Operation Event records. It does not integrate lifecycle transitions, expose event-history APIs, or publish Socket.IO messages; those are subsequent M4.3.3.5 tasks.

## Architectural boundary

- The database is the authoritative operation event history.
- Socket.IO is a best-effort notification transport and is not used by this service.
- The caller owns the database transaction.
- Event persistence failures propagate to the caller so the associated operation transition can be rolled back.
- The service never commits, rolls back, enqueues, or publishes.

## Service contract

Entry point:

```python
record_operation_event(
    operation_id,
    event_type,
    *,
    message=None,
    phase=None,
    progress=None,
    event_data=None,
)
```

Supported event types are `accepted`, `queued`, `started`, `progress`, `log`, `heartbeat`, `cancellation_requested`, `completed`, `failed`, `cancelled`, and `recovery_required`.

The service:

1. Validates the operation identifier and event contract.
2. Requires `progress` and `event_data` to be JSON objects when supplied.
3. Rejects secret-bearing payload keys recursively, while allowing approved `*_ref` keys.
4. Enforces a 64 KiB limit per structured payload, a 2,000-character message limit, and a 140-character phase limit.
5. Locks the parent Infrastructure Operation row using `SELECT ... FOR UPDATE`.
6. Allocates the next per-operation sequence from persisted event history.
7. Inserts an immutable Infrastructure Operation Event with schema version `1.0.0`.

The parent-row lock serializes sequence allocation for concurrent writers targeting the same operation. The DocType's unique operation/sequence constraint remains the final integrity safeguard.

## Transaction ownership

The caller must persist its operation state transition and call `record_operation_event` within the same transaction. The service intentionally does not commit. This ensures the state transition and event are committed or rolled back together.
